# Soloco 飞书反馈契约

提交前始终用 `base +form-detail` 获取实时结构；实时结果优先于本文。

## 目标

首次使用前，将下表占位值替换为你有权使用的飞书多维表格和表单信息。不要把公司内部地址或访问凭据提交到公开仓库。

| 项目 | 值 |
|---|---|
| 收集页 | `<FEISHU_COLLECTION_URL>` |
| 表单分享页 | `<FEISHU_FORM_SHARE_URL>` |
| share token | `<FEISHU_SHARE_TOKEN>` |
| Base token | `<FEISHU_BASE_TOKEN>` |
| table ID | `<FEISHU_TABLE_ID>` |
| 数据表 | `问题反馈` |

## 字段

| 字段 | 必填 | 合法值 / 写法 |
|---|---:|---|
| 你的姓名 | 是 | 优先使用已验证的飞书用户名；无法获取时询问用户 |
| 标题 | 是 | 单一现象，15–60 字 |
| 问题类型 | 是 | `Bug`、`体验问题`、`产品建议` |
| 所属模块 | 是 | `目标与使命`、`运行与任务`、`组织画布`、`通知与收件箱`、`设置与账号`、`客户端安装/更新`、`官网与营销页`、`其他` |
| 严重程度 | 是 | `阻断（完全无法继续）`、`严重（主流程受影响）`、`一般（有绕过办法）`、`轻微（观感/文案）` |
| 问题描述（是什么） | 是 | 通俗说明、预期、实际、证据、可能原因 |
| 复现步骤 | 否 | 只写材料能支持的步骤；未知时写“诊断材料未提供完整步骤” |
| 环境 / 版本 | 否 | 系统、客户端、运行时、诊断包名和完整 SHA-256 |
| 解决建议（怎么解决） | 否 | 用“建议”表述，不冒充已验证修复 |
| 设计建议（怎么设计） | 否 | 仅交互或信息架构问题填写 |

分类规则：执行、等待、恢复和任务状态问题归 `运行与任务`；登录权限归 `设置与账号`；安装启动归 `客户端安装/更新`；证据不足或跨模块归 `其他`。严重程度按用户影响选择，不按错误日志数量选择。

## Payload

```json
{
  "fields": {
    "你的姓名": "飞书用户名",
    "标题": "任务已暂停但界面仍显示运行中",
    "问题类型": "Bug",
    "所属模块": "运行与任务",
    "严重程度": "严重（主流程受影响）",
    "问题描述（是什么）": "通俗说明：……\n预期：……\n实际：……\n证据：……\n可能原因：……",
    "复现步骤": "1. ……\n2. ……",
    "环境 / 版本": "……\n诊断包：example.txt；SHA-256：<full sha256>",
    "解决建议（怎么解决）": "建议：……",
    "设计建议（怎么设计）": ""
  }
}
```

默认不包含附件。dry-run 成功后展示最终字段并询问一次“确认提交这条反馈吗？”；得到针对当前内容的明确确认后再正式提交，不做第二次确认。提交成功要求退出码为 0 且顶层 `ok: true`；随后用诊断包 SHA-256 回查记录。
